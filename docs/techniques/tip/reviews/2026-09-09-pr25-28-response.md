## What changed, per finding

**G1** — the stray `stated_at=posted_at` passthrough is out of `ingest_email`
(email intake restored) and INTO `ingest_manual`'s `process_content` call, so a
recovered old message keeps its authoritative age (replay/expiry apply). Your
two tests assert the actual processing argument.

**G2** — `gateway_spool.jsonl` is now a write-ahead LEDGER: `accept()` persists
every envelope BEFORE the queue (fresh channels included); `drain_spool()`
leases (in-process) instead of erasing; an entry leaves the file only on
`ack()` after destination success; worker cancellation releases (stays
pending); queue overflow defers durably; per-entry backoff ~60·(2^(n−1)−1)s;
retries replay per channel oldest-first and stop a channel at its first
still-failing entry (no close over a failed open, no live event ahead of
recovery — a `pending_min` check defers out-of-order deliveries to the ordered
retry lane). Pending/dead/overflow/IO-error counts print in the status line;
corrupt spool lines are counted, not silently skipped.

**G3** — `_em_forward` raises on non-200 (a 503 is never acknowledged); the
envelope carries a per-destination `emDone` ACK so a tips-side failure retries
only the tips half and never re-delivers to EM; `_recover_gaps` covers
EM-only channels; the cursor advances only after ACK and CONTIGUOUSLY (never
past the oldest undelivered create — a later success cannot hide an earlier
failure). Capped recovery prints and self-continues on the next reconnect via
that contiguity.

**G4** — `mirror_record` preserves field PRESENCE (absent ≠ cleared): a partial
MESSAGE_UPDATE without `content`/`attachments` sends None and the revision
upsert keeps the original text/images. An attachment change invalidates
`local_images` and re-fetches; the first insertion keeps `edited_at`;
duplicate/older revision deliveries are idempotent (no repeat
`TipMessageRevised`).

**G5** — pre-extraction dedupe is an atomic CLAIM: check + write-ahead insert
in one transaction serialized by `pg_advisory_xact_lock` on the message id
(cross-process). Existing row semantics: completed → duplicate; status `new`
with a FRESH `claimedAt` (≤10 min) → in flight, duplicate; status `new` with a
stale/missing claim → RESUMED (crash after storing raw content no longer
strands work). Claim failures raise — the gateway spools and retries; a broken
dedupe check can no longer proceed to a paid extraction. (No schema change:
the advisory lock provides the atomicity; noted as the documented mechanism.)

**E1** — the exact-contract tool ages the OPRA quote itself: ≤120 s presents
as `live` with `source`/`ageSeconds`; older or unknown-age becomes `lastQuote`
`{stale: true}` with an explicit note, never "live". A missing real-time source
is preserved as an evidence gap (`liveNote` on the delayed row). Bar timestamps
now carry the year.

**K1** — historical mode is an explicit ALLOWLIST at dispatch

`close_position`/`update_exit_plan`/`disarm_plan` and every current-state read

**K2** — a missing/invalid `asOfMs` REFUSES time-dependent tools (no silent
fall-through to current bars); as-of bars keep only bars CLOSED by the tip's
