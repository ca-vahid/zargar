## Per-finding status

| Finding | Status in v0.7.65 |
|---|---|
| **R63-01 (P1)** — ordinary rule creation bypassed dispute protection through prose-family matching. | **Fixed at the shared boundary.** `supersede_tip_notes` (the one supersession primitive) now locks each row (`FOR UPDATE`) and refuses a `needs_human` row outright. `_supersede_rule_family` runs in ONE transaction with the family rows locked: clean members are superseded (snapshot first), a DISPUTED member is never touched, and the newcomer is **staged as disputed too** (`needs_human=True`, snapshot reason `flag`) — a contradictory refinement cannot enter the rulebook as uncontested advice; the journal records `disputedKept` + `stagedReplacement`. Every automatic writer (analyst `save_note`, retro, digest promotion) reaches supersession only through these two paths; the audit batch already enforced the same invariant. Test: `test_ordinary_rule_writer_cannot_supersede_an_unresolved_dispute`. |
| **R63-02 (P2)** — deleting an already-superseded note rewrote history. | **Fixed.** Every transition into deletion snapshots first and advances the revision; the note keeps its existing `superseded_by` (the replacement link) and gets a `deleted_at` tombstone stamp (new column); a live note additionally gets `superseded_by='deleted:user'` so every live list still excludes it. A repeat delete is a no-op (no revision minted; the API keeps its 404). `note_dict` exposes `deletedAt`; the Knowledge tab's history pill says "deleted" and names the earlier replacement. Test: `test_deleting_superseded_note_preserves_earlier_replacement_provenance`. |
| **R63-03 (P2)** — a repeatedly failing oldest group starved untouched groups. | **Fixed.** Per-scope progress records last attempt, last success and `retryAfter`; ordering is untouched-first, then oldest attempt; a failed scope backs off (23 h → 47 h → 95 h) and after `MAX_GROUP_ATTEMPTS = 3` is set aside for the cycle, visibly (`groupsGivenUp`). Failed work is journaled explicitly: a `tip_knowledge_batches` receipt with `status='failed'` (error + paid calls) per attempt, plus the run-level journal payload. Progress survives restart (cycle row + receipts hydrate the engine's state). Test: `test_failed_scope_does_not_starve_untouched_scope`. |
| **R63-04 (P2)** — bounded audits never finished a cycle in propose-only mode (deferred recomputed from all eligible scopes every run → permanent partial → daily paid catch-up). | **Fixed.** New table `tip_knowledge_cycles`: a cycle records its eligible scope set (with the rulebook as pseudo-scope `rule`) and per-scope status pending/done/failed/dropped with attempts and the revision-set hash judged. Each tick audits PENDING work only (budget `knowledge_audit_max_groups`); the rulebook is judged once per cycle; scopes that become eligible mid-cycle join as explicit `discovered` follow-up work; scopes falling below the floor are dropped. The cycle completes when nothing is pending → maintenance status `done` → the watermark advances → not due until next week. Applying proposals is NOT a completion condition. Test: `test_completed_bounded_cycle_can_advance_completion`. |
| **R63-05 (P2)** — invalid JSON lost the run's paid-call usage; an opening `{` suppressed the retry. | **Fixed.** `_judge` records every call before parsing and raises `JudgeError(calls=…)` on any failure (provider error, timeout, validation); callers persist those calls on the run row and in the payload's `usage` (the failed group's error entry sits beside its call records). The bounded repair triggers on validation failure — at double the cap when the stop reason was `max_tokens`, at the same cap otherwise — ONE retry, ceiling 8,192, no loop. Test: `test_invalid_audit_json_keeps_paid_call_usage`. |
