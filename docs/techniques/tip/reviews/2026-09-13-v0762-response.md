Reviewer verdict on v0.7.62: **"Not a full GO yet."** Seven new boundary tests
failed, the automatic audit had already acted on live knowledge, and the
recommendation was to make knowledge maintenance **propose-only until the
application safeguards are fixed**. This document is the per-tag status of
that work. The reviewer's three regression files were adopted verbatim
(`tests/test_kb_atomic_followup.py`, `tests/test_kb_retrieval_followup.py`,
`tests/test_census_0762_followup.py`) and all pass, alongside the earlier
adopted files.

## The correction first

My v0.7.62 response said "bulk apply HELD". That was true of the manual
consolidation packet and false of the scheduled path: the new
`tip_knowledge_maintenance` job's catch-up ran immediately after the deploy
and, in `source:trading-floor`, superseded two notes (`31b0b7c7…` and a
sibling) with a merged note `571a93dc…`. The rule audit in the same run
returned an EMPTY model reply (`input_value=''` — the 2,000-token cap was
reached before any JSON), 11 groups failed, 20 `ticker:*` groups were
deferred behind alphabetical `source:*` groups, and the two kill-switch rules
(`dbfd8177…`, `7e72fd7f…`) were NOT flagged in persisted state — my response
text claimed they were.

Immediate action (before writing any code, 2026-09-13): the runtime setting
`techniques.tip.rule_audit_enabled` was switched OFF through the journaled
settings API so no second scheduled run could act. It is switched back on
only after this release is deployed, because from this release on the job
cannot apply anything (below).

The applied trading-floor merge is left in place: reverting it is itself a
revision transition (KB-03) and the reviewer asked for no silent knowledge
edits during consolidation. It is listed in the consolidation packet as a
human decision.

## What propose-only means operationally

- The daily `tip_knowledge_maintenance` job keeps running (re-enabled after
  deploy) and keeps paying for the judge calls — but its output is a
  proposal receipt plus contradiction flags. Nothing else changes a live note.
- A human reviews proposals in the Knowledge tab. There is deliberately no
  one-click "apply this proposal" yet: applying a stale proposal would need
  the same revision check, and the consolidation packet's policy decisions
  come first.
- Turning apply on is a settings change (`techniques.tip.knowledge_apply_enabled`),
  journaled like every other knob — it is not on the release path.
